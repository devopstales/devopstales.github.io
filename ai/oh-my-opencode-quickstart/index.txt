## Install in Minutes

Prerequisites: working OpenCode plus at least one configured provider (`opencode auth login`, credentials in the auth store). Then pick a route — agent-driven install by pasting the upstream installation prompt into OpenCode (answers provider questions, registers the plugin), interactive installer (`bunx oh-my-opencode install`, non-interactive flags available for provisioning), or manual clone plus install script with explicit config path fallback:

```bash
bunx oh-my-opencode install
```

```bash
git clone https://github.com/code-yeongyu/oh-my-opencode.git ~/.oh-my-opencode
cd ~/.oh-my-opencode
npm install
npm run install
```

Name quirk: upstream rebranded to oh-my-openagent, but packages, commands, and configs still say oh-my-opencode — same thing, don&#39;t let community posts confuse you.

Verify three things before real work: config file present (project `.opencode/oh-my-opencode.json` over user-level), a specialist invocable (`opencode run &#34;Use @oracle to analyse the architecture of the current project&#34;`), and keyword triggering (`opencode run &#34;ulw list all configuration files in this project&#34;`). All green means ready, not just installed.

## Two Concepts, One Config

`ultrawork` (or `ulw`) is a hard mode switch, not a hint: background parallel execution, LSP integration, context management, automatic decomposition activate structurally. Specialists (`@oracle` for architecture, `@librarian` for research) route explicitly or via orchestrator. Full roster mechanics in the [agents deep dive](/ai/oh-my-opencode-agents/); honest cost data in the [experience report](/ai/oh-my-opencode-experience/).

Config merges project over user-level, JSONC keeps comments legal, and `$schema` buys editor autocomplete over typo-driven wasted runs:

```jsonc
{
  &#34;$schema&#34;: &#34;https://raw.githubusercontent.com/code-yeongyu/oh-my-openagent/dev/assets/oh-my-opencode.schema.json&#34;,

  &#34;sisyphus&#34;: {
    &#34;enabled&#34;: true,
    &#34;max_concurrent_tasks&#34;: 2,
    &#34;task_timeout&#34;: 300
  },

  &#34;agents&#34;: {
    &#34;oracle&#34;: {
      &#34;enabled&#34;: true,
      &#34;model&#34;: &#34;openai/gpt-5.2&#34;,
      &#34;variant&#34;: &#34;high&#34;,
      &#34;temperature&#34;: 0.7,
      &#34;prompt_append&#34;: &#34;Provide concise tradeoffs and a clear recommendation&#34;
    },
    &#34;librarian&#34;: {
      &#34;enabled&#34;: true,
      &#34;model&#34;: &#34;google/gemini-3.1-pro&#34;
    }
  },

  &#34;categories&#34;: {
    &#34;quick&#34;: { &#34;model&#34;: &#34;opencode/gpt-5-nano&#34; },
    &#34;visual-engineering&#34;: { &#34;model&#34;: &#34;google/gemini-3.1-pro&#34; }
  }
}
```

Concurrency 2 starts safe — provider ceilings (Claude Max20: 3 parallel) punish ambition with flaky timeouts. Per-agent and per-category routing plus MCP/hook integration graduate from here; resolution runs override, then fallback chain, then default, so misconfiguration degrades to weaker models rather than failing silently.

## Copy-Paste Workflows

Architecture review on unfamiliar code: launch, ask `@oracle` for bounded contexts, dependency edges, highest-risk components, and a small-PR refactor plan — read-only advisory, no accidental edits. Scripted variant skips the TUI via `opencode run`. Full-feature builds go ultrawork (`opencode run &#34;ultrawork implement /health with readiness plus liveness, tests, docs, local verification&#34;`), optionally steering design first (`ultrawork ask @oracle to design the contract, then implement minimally with tests`) — orchestration plus explicit specialist control is the sweet spot, with concurrency inside provider limits or speed turns unreliable.

## Troubleshooting Shortlist

Dead keyword means plugin loading or version regression around keyword detection — confirm registration and configs, then upgrade. Missing config path means verify install and export the explicit path before reinstalling. Throttling means reduce concurrency and rerun — parallelism against limits never wins. Skip ultrawork for single-file edits and quick questions where tokens and rate limits exceed any gain. And review provider terms before automated parallel scale: working integration doesn&#39;t equal permitted integration.

## Summary

Base OpenCode running, plugin installed three ways, three checks green, `ultrawork` understood as structural switch, concurrency conservative, routing layered. Complexity reserved for multi-file multi-phase work — everything else stays a plain prompt.
